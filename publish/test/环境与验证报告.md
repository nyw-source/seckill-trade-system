## 4. 揪出的 4 个 blocker（3 个已修，1 个要你在 VM 上动手）

### 4.1 🔴 Nacos 9848 不通 → 所有服务注册不上（要你动手）

Nacos 2.1.0 standalone 在 `.130:8848` 是活的（`/nacos/v1/ns/operator/metrics` 返回 UP），
但 gRPC 端口 9848/9849 **连接超时**。Nacos 2.x 客户端必须走 9848，所以服务一定会注册失败。
修复命令见 2 节末尾。

### 4.2 🔴 秒杀表在库里压根不存在（已修）

`nyw` 库原本只有 8 张表：`address / cart / item / order / order_detail / order_logistics / pay_order / user`，
**没有 `seckill_voucher`、没有 `seckill_order`**。`SeckillVoucherMapper.selectById` 一查就是
`Table 'nyw.seckill_voucher' doesn't exist`。

已按项目自带的 `test/jmeter/init-seckill-test.sql` 建好（含 `voucher_id=1`、`stock=3000`），现在表已就位。

### 4.3 🔴 死信链路永远不触发（已修）

`seckill.order.queue` 既配了 `x-message-ttl(15min)` 又有消费者，消息消费即 ack 删除，
永远不会过期 → 永远进不了死信队列 → `closeTimeoutOrder` 生产上跑不到。
已改为独立延迟队列 + routing key 扇出，并在真实 broker 上验证通过（见 C 段）。

### 4.4 🔴 分布式 ID 生成器 100% 抛异常（已修，这条最要命）

原实现：

```java
String timestamp = now.format(ofPattern("yyyyMMddHHmmss"));  // 14 位
String idStr = timestamp + String.format("%06d", seq);       // 拼出 20 位
return Long.parseLong(idStr);                                // ← 这里必炸
```

实测（JDK 17 直接跑）：

```
拼接出的 ID    : 20260922170617000001 （20 位）
Long.MAX_VALUE : 9223372036854775807   （19 位）
ID > Long.MAX  : true
parseLong 异常 : NumberFormatException: For input string: "20260922170617000001"
```

20 位十进制数 ≥ 1×10^19，必然超过 `long` / MySQL `BIGINT` 上限 9.22×10^18，
所以 `Long.parseLong` 每次都抛 `NumberFormatException`（连退一步落库也会 `DataError 1264 Out of range`）。
调用点有两个：`SeckillServiceImpl:98`（秒杀下单）、`OrderServiceImpl:62`（普通下单）——
**意味着秒杀接口和下单接口一调就 500**，与代码写得漂不漂亮无关。

已改成经典位移方案：

```java
long timestamp = Instant.now().getEpochSecond();
Long seq = stringRedisTemplate.opsForValue().increment(key);
return (timestamp << 32) | (seq & 0xFFFFFFFFL);   // 结果 19 位，BIGINT 安全
```

实测输出 `7688283526206062593`（19 位），`seq` 取到 42 亿仍不越界；2038-01-19 之前安全。

> ⚠️ 简历措辞要跟着改：原来写「14 位时间戳 + 6 位序号拼接」→ 改成
> **「时间戳左移 32 位 | Redis INCR 序列号，趋势递增且落在 BIGINT 范围内」**。

### 4.5 🟠 `DistributedIdGenerator` / `CacheServiceImpl` 扫不到（已修）

两个类在 `com.nyw.common` 包下，而微服务启动类在 `com.nyw.seckill` / `com.nyw.order`，
`@SpringBootApplication` 只扫自己包及子包；`nyw-common` 的 `spring.factories` 里也没注册它们。
结果 `SeckillServiceImpl`、`OrderServiceImpl` 构造注入 `DistributedIdGenerator` 时会
`No qualifying bean` 直接启动失败。已给两个启动类加 `scanBasePackages = "com.nyw"`。

（单体 `nyw-service` 的启动类在 `com.nyw` 包下，扫描范围天然覆盖 `com.nyw.common.**`，
所以单体一直是好的 —— 这也解释了为什么拆微服务后才炸。）

## 5. 环境约定备忘

- Redis 与 RabbitMQ 都是**多项目共用**的：
  - Redis db0 里有 32 个别家 key（`sys:cache:dict::*`、`icrorder:*`、`shop:geo:*`、`blog:liked*`），nyw 靠 `nyw:` 前缀隔离；担心污染可加 `database: 1`。
  - RabbitMQ 上有 `queue_email_message`、`queue_flowable_project` 等别家队列，不影响 `seckill.*`。
- Sentinel 控制台 `.130:8090` 没起，服务启动时只会打印「拉不到规则」的告警，不影响功能。
- 本机 `mvn` 直接敲会报 `ClassNotFoundException: plexus-classworlds.launcher.Launcher`，需用 java 直拉 Launcher，命令见 `.workbuddy/memory/MEMORY.md`。
